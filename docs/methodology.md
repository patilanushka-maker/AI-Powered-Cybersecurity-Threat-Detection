# Modeling Methodology & Evaluation Framework

## 1. Machine Learning Strategy

The system implements a supervised intrusion detection prototype using Scikit-learn pipelines.

### 1.1 Current Task: Binary Intrusion Classification
The initial objective maps network flows to binary security states:
- **`0` = Benign**: Normal baseline network communication.
- **`1` = Attack**: Malicious activity (DoS, DDoS, PortScan, Brute Force, Infiltration, etc.).

Label mapping is enforced via `encode_binary_target()`:
- `benign_label="BENIGN"` maps to `0`.
- Recognized attack labels map to `1`.
- Missing, empty, or unknown labels outside whitelists are strictly rejected to prevent silent misclassification.

### 1.2 Model Selection & Architecture
- **Primary Model**: **Random Forest Classifier** (`RandomForestClassifier`)
  - **Starting Hyperparameters**:
    - `n_estimators=100`
    - `random_state=42`
    - `class_weight="balanced"` (compensates for severe imbalance between benign background traffic and rare attacks)
    - `n_jobs=-1` (multiprocessing across available cores)
  - **Feature Scaling**: Omitted by design. Random Forest decision splits depend strictly on monotonic feature ordering and are invariant to numerical scale.
- **Configurable Baseline**: **Logistic Regression** (`LogisticRegression(class_weight='balanced')`) is supported via the configurable `estimator` argument in `train_model()`.

## 2. Leakage-Aware Pipeline Architecture

To guarantee strict separation between training and evaluation phases:
1. **Splitting Precedes Transformation**:
   - `train_test_split_network_flows()` partitions features `X` and labels `y` prior to fitting any data-dependent transformers.
2. **Unified Scikit-learn Pipeline**:
   - Training pipeline packages `SimpleImputer(strategy='median')` and `RandomForestClassifier`.
   - The median imputation statistics are learned **exclusively on `X_train`**.
   - During evaluation or inference, `pipeline.predict()` and `pipeline.predict_proba()` apply the training-learned median to test data without recomputing statistics.
3. **Identifier & Timestamp Exclusion**:
   - Session identifiers (`Flow ID`, `Source IP`, `Destination IP`, `Timestamp`) are excluded from features to prevent memorization and temporal leakage.

---

## 3. Data Splitting: Stratified vs. Temporal

### 3.1 Stratified Random Partitioning (`train_test_split_network_flows`)
- Preserves exact class proportions in train and test partitions.
- Minimum requirement: at least 2 samples per class to ensure stratification.
- **Limitation**: Stratification alone does NOT eliminate leakage when network captures contain repeated identical flows, TCP re-transmissions, or multi-packet flows captured at the identical millisecond.

### 3.2 Chronological Partitioning (`split_data_temporal`)
- When genuine capture timestamps are present, flows are partitioned chronologically (e.g. earliest 80% train, subsequent 20% test).
- Reflects realistic SOC deployment where models train on past telemetry to predict future intrusions.

## 4. Evaluation Framework & Metric Definitions

Held-out evaluation metrics strictly evaluate test performance:

| Metric | Formula / Implementation | Security Significance |
| :--- | :--- | :--- |
| **Accuracy** | $(TP + TN) / (TP + TN + FP + FN)$ | General metric; uninformative under extreme class imbalance. |
| **Detection Rate (Recall / TPR)** | $TP / (TP + FN)$ | Critical: Ratio of true attacks successfully detected. |
| **Precision** | $TP / (TP + FP)$ | Operational: Ratio of true attacks among raised alarms. |
| **False Positive Rate (FPR)** | $FP / (FP + TN)$ | SOC Vital: Rate of benign flows incorrectly flagged as attacks. |
| **F1-Score** | $2 \cdot \frac{Precision \cdot Recall}{Precision + Recall}$ | Harmonic mean of precision and recall. |
| **ROC-AUC & PR-AUC** | Area under ROC / PR curves | Evaluates ranking discrimination across all classification thresholds. |

### Technical Considerations
- **Positive-Class Semantics**: Positive class is explicitly `pos_label=1` (Attack).
- **Probability Indexing**: Probability scores query `model.classes_` dynamically rather than assuming column index `1` is the positive class.
- **Zero-Division Policy**: `zero_division=0.0` prevents crashes when classes have zero positive predictions.

## 5. Artifact Persistence & Security

- **Path**: Trained pipelines are saved to `models/random_forest_baseline.joblib`.
- **Overwrite Protection**: `save_model_artifact(..., overwrite=False)` raises `FileExistsError` if a file exists, preventing accidental overwriting.
- **Security Warning**: Only load `.joblib` artifacts generated by trusted internal pipelines. Deserializing untrusted binaries executes arbitrary code.
